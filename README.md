# Examination Scheduler — Flask + SQLite + OR-Tools CP-SAT

## Run

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

Open http://127.0.0.1:5000

## Optimization model

- Each enrolled subject is assigned exactly one time slot.
- Subjects sharing a student cannot use the same slot.
- Total student-subject exam seats in a slot cannot exceed the sum of capacities of the largest `min(room_count, faculty_count)` rooms.
- Rooms can contain multiple subjects in the same slot; room capacity applies to the combined student count.
- Each active room has one invigilator; a faculty member is assigned at most once per slot.
- The objective is to minimize the number of used slots.

## Continuous optimization

Optimization has **no time limit**. CP-SAT continues searching until it proves optimality or the user presses **Stop optimization**.

- The solver runs in a background thread, so the Flask UI remains responsive.
- Whenever CP-SAT finds a strictly better feasible schedule (fewer time slots), the app atomically replaces the saved allocations and invigilations in SQLite.
- The UI displays elapsed time, the current best slot count, and the elapsed time at which that best schedule was found.
- Finding another feasible schedule with the same slot count does not change the "current best found at" time.
- Pressing Stop requests CP-SAT cancellation. The best schedule already saved in SQLite is retained and shown after the worker finishes stopping.
- Only one optimization job can be active at a time. The singleton job claim is stored transactionally in SQLite, so another start request is rejected while a job is running.
- Job status, elapsed time, best slot count, and best-found timestamp are persisted in SQLite. Reloading the page restores the active job and resumes status polling, or restores the finished job and its saved schedule.
- If the Flask server restarts during optimization, the job is marked `INTERRUPTED`; the last saved feasible schedule remains available. The solver itself is not resumed automatically.
- If stopped before any feasible schedule is found, there is no new schedule to show.
- `OPTIMAL` means CP-SAT proved the minimum number of slots. `STOPPED` with a schedule means a feasible schedule was saved, but optimality may not have been proven.

## API

- `POST /api/data` — import initial JSON data.
- `POST /api/schedule/start` — start a background optimization. Optional JSON: `{"workers": 8}`.
- `GET /api/schedule/status/<job_id>` — status, elapsed seconds, best slot count, best-found elapsed time, and current best schedule.
- `GET /api/schedule/current` — restore the current/most recent job and saved schedule after a page reload.
- `POST /api/schedule/stop/<job_id>` — request cancellation.
- `GET /api/schedule/result/<job_id>` — retrieve the saved schedule.
- `GET /api/summary` — dataset counts.

The worker count defaults to `EXAM_SOLVER_WORKERS` or up to 8 available CPUs. Set `EXAM_SOLVER_WORKERS=8` to override it.

## Notes

The optimization assumes students are interchangeable seats for room-capacity purposes. It then deterministically packs student-subject exam seats into rooms, allowing different subjects in one room. This is valid because no student can have two conflicting subjects in the same slot.

For production deployment, disable Flask debug mode and add authentication, authorization, CSRF protection, and database backups. Run a single Flask application process so the Stop request can reach the in-memory CP-SAT solver instance.


## Best-schedule history

Every time CP-SAT discovers a strictly better feasible schedule (fewer time slots), the app records:
- elapsed time since optimization started;
- the new best number of time slots.

The history is stored in SQLite in `optimization_history`, returned by the status and current-job APIs, and restored after page reload. The UI displays both a time-versus-slots chart and a table. Non-improving feasible solutions are not added.

The Stop behavior remains the original direct CP-SAT `StopSearch()` implementation. CP-SAT may take some time to respond to cancellation; the UI displays `Stopping…` until the solver returns.
